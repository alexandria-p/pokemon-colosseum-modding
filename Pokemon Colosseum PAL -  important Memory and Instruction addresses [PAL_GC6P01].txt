# Assorted information (all tested on Makuhita fight, first shadow encounter) (Rom: PAL_GC6P01):
Save base changes between sessions, which can affect the location of these memory addresses below.  Always re-read 0x804C8268 at start of each session. Recalculate all memory addresses from new base. 

For reference, shadow registry base is (save_base + 0x82B0) - in my below info my save base is 0x80455CF4 , so I list the shadow registry as 0x8045DC90

# Useful breakpoints
### Instruction breakpoints:
0x801F3080 - Fires once only, during swirl effect at beginning of battle - suspect this fires for the 1 shadow pokemon the enemy has.

0x8012954C - I believe it is getting called every time a pokemon is shown onscreen in battle. It references the pokemon's PID in the register (read-only). Perhaps they are calculating if it is shiny, in order to apply the shiny shader to the pokemon visually.

### Memory breakpoints
0x80589D30 - Shadow pokemon identifier (????????? is it?)

0x8045DC90 - Shadow Registry section of the memory

0x8045DD00 - Makuhita's slot (PID2) in the Shadow Registry. Starts as E9F49EE6  before first encounter.
Save base = 0x804559E0
Shadow registry = save base + 0x82B0 = 0x8045DC90
Entry 9 PID2 = registry + (9 × 12) + 4 = 0x8045DC90 + 0x6C + 0x4 = 0x8045DD00

0x80455CF4 - Fired AFTER the battle ended, with shadow pokemon caught. This is when the shadow pokemon's PID is being copied from unknown_address_5 (0x804BB530) and written to the permanent party slot 3 (0x80455CF4) in memory.

## Trigger: Battle begins (swirl animation)
 ↓ 
Makuhita's old PID "E9F49EE6" is copied from his slot in the Shadow Registry (0x8045dd00) and written to unknown_address_1 (0x8058923C)
 ↓ 
PID is generated
 ↓ 
PID is written to unknown_address_2 (0x80589D34) - this is the first time this PID is saved anywhere!
*Happens at instruction breakpoint 0x80121FC4 (stw r4, 0x0004(r3)), if you set conditional r4 == New PID and r3 == 0x80589D30*
 ↓ 
PID is written to unknown_address_3 (0x80470A08)
 ↓ 
PID is written from unknown_address_3 (0x80470A08) to unknown_address_1 (0x8058923C), and to unknown_address_4 (0x804C0778)

Trigger: Shadow pokemon (Makuhita) is thrown onto the field
**Can hit with a memory breakpoint (write) on PID2 in the Shadow Registry (0x8045DD00) **
 ↓
PID is written from unknown_address_1 (0x8058923C) to Makuhita's PID2 slot on the Shadow Registry (0x8045DD00)

Trigger: Shadow pokemon is caught mid-battle
**Happens at instruction breakpoint 0x8012379C (stwu r0, 0x0008(r5))**
**Can hit with a memory breakpoint (write) on unknown_address_5 (caught pokemon's battle buffer?)(0x804BB530)**
 ↓
PID is written to unknown_address_5 (caught pokemon's battle buffer?)(0x804BB530) 

## Trigger: Battle ends (and shadow pokemon was caught)
*Happens at 0x8012EEBC (stwu r0, 0x0008(r5))*
*Can hit with a memory breakpoint (write) on permanent party slot 3 (0x80455CF4)*
 ↓
writes PID from unknown_address_5 (caught pokemon's battle buffer?)(0x804BB530) to Party slot 3 (0x80455CF4)

# Where Shiny value is calculated and set (in Pokemon Colosseum PAL)
0x80128584 (ram/memory address)
*If you want to catch when this is written to, put a (write) memory breakpoint in here.*

According to Stars, this is the ram address of the function in PAL which does the pid roll (and reroll if it doesn't match what it needs) 
At this point, the memory registers include:
- r7 - the trainer id to check against
- r6 - whether or not the PID rolled should be a shiny against the TID/SID value in r7 
     - 0 for no shiny, (shiny lock)
     - 1 to force shiny, 
     - (-1) for random shininess

What happens *after* the PID is rolled here? (Example PID used: 6DA9D62A)

- At instruction address (801b207c), I can see the first half of the newly generated PID (6DA9) is set into r3
- At instruction address (801b207c) again, I can see the second half of the PID (D62A) is set into r3 (where r3 value = 0000d62a)
- At instruction address (801285d4), (D62A)  has now been set into r0 (where r0 value = 0000d62a) 
- At instruction address (801285d8), I can see the full PID (6da9d62a) has been set into r31 (where r0 value = 6da9d62a)
