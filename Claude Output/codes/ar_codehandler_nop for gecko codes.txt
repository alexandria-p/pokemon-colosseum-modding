CORRESPONDENCE
-------------------------------------------------------------------------------
The first six lines write nop (60000000) over a check.  The last two write
data values, not instructions — the values are identical in both regions, only
the destination moves.

-------------------------------------------------------------------------------
NOTE — map_convert.py false negatives in this region
-------------------------------------------------------------------------------
The size-sequence aligner reported "NO ALIGNED COUNTERPART" for 80005614 and
80005D1C.  That is a false negative, not a wrong answer: the containing
functions differ slightly in size between builds

    zz_00055e0_   PAL 0xE8   US 0xE4
    zz_00057d0_   PAL 0x564  US 0x48C

so the aligner refuses to pair functions that are plainly counterparts.  Below
roughly 0x80006000 the two builds diverge enough that size alignment stops
working.  Fall back to anchoring on a symbol that is *named* in both maps —
GSgfxResetUpdate did the job here — and offset from it by hand.
