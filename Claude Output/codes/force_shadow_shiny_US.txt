Disassembly (hook = first instruction of the PID generator):
    li     r6, 1                ; shiny flag argument = forced shiny
    lis    r7, 0x8047
    ori    r7, r7, 0xADB8       ; r7 = &saveBasePtr        (US global)
    lwz    r7, 0(r7)            ; r7 = saveBase
    lwz    r7, 0x9C(r7)         ; r7 = player trainer ID dword
    rotlwi r7, r7, 16           ; swap halves into the order this fn expects
    stwu   r1, -0x40(r1)        ; the overwritten original instruction
    (00000000 = padding to a whole 8-byte line)

ori zero-extends its immediate, so the global splits straight down the middle:
0x8047ADB8 -> lis 0x8047 / ori 0xADB8.  (Contrast the lis/lwz form used in
all_new_pokemon_shiny_US.txt, where the displacement sign-extends.)

r7 must be overridden because the caller passes the *AI trainer's* ID.  A PID
rolled shiny against that would stop being shiny the moment you owned it.

VERIFIED against a US MRAM dump (2026-09-04)
-------------------------------------------------------------------------------
* 0x80124410 reads 9421FFC0 (stwu r1,-0x40(r1)).  The code's last line is
  correct.
* The function's prologue is
      stwu r1,-0x40(r1) / mflr r0 / stw r0,0x44(r1) / stmw r21,0x14(r1)
      mr. r24,r3 / mr r25,r4 / mr r26,r5 / mr r27,r6
  i.e. r4 = gender, r5 = nature, r6 = shiny, exactly as the symbol name says.
  Setting r6 = 1 at the hook is correct and lands before the callee reads it.
* The hook address 0x80124410 is corroborated from outside: the PAL author's
  own US conversion of the all-new-shiny code patches 0x8012442C, which is
  0x80124410 + 0x1C — the mr r27,r6 in this function's prologue.  That only
  makes sense if the function base is 0x80124410, where this code hooks.
* The save-base global 0x8047ADB8 is confirmed independently:
  savedataBiosSetNowSavedataPtr (0x80128E14) is
      cmplwi r3,0 / beqlr / stw r3,-0x5A68(r13) / blr
  with r13 = 0x80480820, so the global is 0x80480820 - 0x5A68 = 0x8047ADB8.
