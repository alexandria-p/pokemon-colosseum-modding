Disassembly:
    li     r6, 0             ; the overwritten original instruction
    cmplwi r30, 0            ; r30 = the game's own is-shadow flag
    beq    done              ; ordinary Pokemon -> leave r6=0, r7=r25 untouched
    lis    r11, 0x804C
    ori    r11, r11, 0x8268  ; r11 = &saveBasePtr  (PAL 0x804C8268)
    lwz    r11, 0(r11)       ; r11 = save base
    cmplwi r11, 0
    beq    done              ; no save loaded -> leave alone
    lwz    r7, 0x9C(r11)     ; player's (SID << 16) | TID
    rotlwi r7, r7, 16        ; -> (TID << 16) | SID, the order this fn wants
    li     r6, 1             ; force shiny
  done:
    nop                      ; branch target (0x801FECC0)

12 instructions = 6 lines exactly.  Both branches are PC-relative within the
block, so they stay correct wherever the codehandler copies it.


-------------------------------------------------------------------------------
WHAT CHANGED FROM THE US BUILD
-------------------------------------------------------------------------------
Only two things:

    hook    US 0x801FA3E8   ->   PAL 0x801FEC94
    global  US 0x8047ADB8   ->   PAL 0x804C8268
              (lis 0x8047 / ori 0xADB8  ->  lis 0x804C / ori 0x8268)

Everything else is byte-identical.  ori zero-extends, so no sign-extension
correction is needed in either region.

Note the hook sits one instruction after 0x801FEC90, which the PAL
"all new generated Pokemon are shiny" code hooks.  Do NOT enable both.


-------------------------------------------------------------------------------
THE HOOK SITE
-------------------------------------------------------------------------------
Inside the PAL battle-Pokemon generator (0x801FE824), the region is
instruction-for-instruction identical to the US one apart from bl targets:

    801FEC44  cmplwi r30, 0
    801FEC48  beq    0x801FEC84      ; not a shadow -> roll a new PID
    801FEC4C  mr     r3, r23
    801FEC50  bl     0x801F3168      ; does this shadow already have a PID?
    801FEC5C  bne    0x801FEC84      ; no -> roll a new PID
    801FEC64  bl     0x801F2FC4      ; YES -> fetch the stored PID
    801FEC7C  bl     set field 111   ; ...and use it
    801FEC80  b      0x801FECB4      ; generator skipped entirely
    801FEC84  mr     r3, r31
    801FEC88  mr     r4, r29
    801FEC8C  mr     r5, r28
    801FEC90  mr     r7, r25         ; OT trainer id argument
    801FEC94  li     r6, 0           ; <- HOOK.  the shiny-flag argument.
    801FEC98  bl     0x80128584      ; the PAL PID generator
    801FECB4  cmplwi r30, 0          ; r30 tested again to gate shadow setup

r30 is the game's own is-shadow flag: written once at 0x801FE8B0
(`rlwinm r30, r3, 0, 24, 31`, from pokemon-data field 19), never written again in
this function, and branched on by the game itself at 0x801FEC44 and 0x801FECB4.

0x80128584 is the PAL PID generator -- the address the original PAL
force-shadow-shiny code hooked directly.  This code sets its arguments at the
call site instead, which is what makes the shadow gate possible.


-------------------------------------------------------------------------------
FIRST ROLL ONLY, AND THE PID PERSISTS
-------------------------------------------------------------------------------
From the branch structure above:

  * FIRST encounter with a given shadow Pokemon -- 0x801F3168 reports no stored
    PID, so the generator runs and this code forces the roll shiny against the
    player.  The result is written to field 111 and, when the Pokemon is sent
    onto the field, into the Strategy Memo in the save.

  * EVERY LATER encounter -- 0x801F3168 reports a stored PID, so 0x801F2FC4
    fetches it and `b 0x801FECB4` skips the generator completely.  This code
    never runs for that Pokemon again.

Practical consequences:
  * enable it BEFORE the first encounter with each shadow Pokemon
  * enabling it later cannot change a PID that is already fixed
  * disabling it later does not undo one
  * leaving it enabled is free

USING IT
-------------------------------------------------------------------------------
Enable together with codes/fix_shadow_shiny_glitch_PAL.txt and the PAL anti-AR
NOP set, with Dolphin in JIT64 SC mode.
